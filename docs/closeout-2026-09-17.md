# Project closeout - 17 September 2026

## Implemented behavior

- Executive approval routes are configured by the responsible administrator on the existing workflow settings screen. No executive users are seeded or chosen automatically. Missing routes are visible on the document list and settings page. NPD/off-contract/marketing-cost drafts can be saved, but cannot be submitted until a valid executive route exists.
- The backend derives approval progress from the stored snapshot and authenticated approver. It rejects skipped transitions and inactive/missing approvers. Removing the executive template before escalation leaves the normal approval unchanged. Once escalated, the document retains its own route snapshot. Normal routes may remain empty for the existing manager approval flow.
- Customer-profile INSERT/UPDATE/DELETE triggers update historical category/corporate columns atomically. Migration `20260917_customer_profile_rollups_v1` adds a customer index and reconciles existing mismatches once. Quantities, money, and invoice counts remain unchanged. Browser grouping caches are invalidated after successful writes.
- Attachment routes share one implementation without moving existing BLOBs or changing their API contracts. The shared approval helper serves both browser and backend; deployed HTML embeds it. LAN hosting serves only its specific public JS path.
- Both builds use `deploy-shared/api-config.js`. Set `TGM_API_BASE_URL` to a valid HTTPS origin; paths, credentials, query strings and fragments fail the build. The current quick-tunnel origin remains the default.
- Regression testing also exposed checkbox clicks that changed their visual state without updating the group/category/branch filter. Those clicks now use the same selection handler as the row.
